技术选型方面，我计划做一个模块化的 RAG(Retrieval-Augmented Generation)系统，以该系统作为整个电能质量报告审查项目的技术后端，同时把它包装成一个 MCP Server (Model Context Protocol)，这样方便我整个系统的扩展。

通信方式使用 Stdio Transport(本地子进程模式)，不做 HTTP 部署。

- “教是最好的学”——我会边做边录视频教学，所以架构设计要清晰、易于讲解
- 配套有技术文档、代码示范和视频讲解
- 每个模块会整理面试高频题和简历撰写建议

**我已有的技术方向 (需要体现在文档中)**
1. RAG 策略:
- 智能分块(语义感知，不是简单定长切分)/ 多层次切分(切分为父子文档，当检索到的子文档同属于一个父文档的数量超过 k(默认取 3)时，直接召回父文档)+上下文增强(元数据、图片描述注入 chunk)
- 混合检索：BM25(稀疏)+Dense Embedding(稠密)，用 RRF 融合
- 精排重排：支持 Cross-Encoder 和 LLM Rerank，两段式(粗排→精排)

2. 全链路可插拔架构：
- LLM、Embedding、Reranker、VectorStore、Splitter、Evaluator 都要能通过配置切换
- 工厂模式 + 抽象基类 + 配置驱动(settings.yaml)
- 首批实现：OpenAI、QWEN、VLLM、DeepSeek(LLM)；Pg Vector(向量库)；LangChain RecursiveCharacterTextSplitter (切分)

3. 多模态：采用 Image-to-Text 策略(Vision LLM 生成图片描述，缝进 chunk 文本)，不用 CLIP 多模态向量

4. 可观测性：
- 全链路 Trace(Ingestion 链路 + Query 链路)，用结构化 JSON Lines 日志 
- Vue 3 + Vite 技术栈构成 Dashboard，不依赖 LangSmith 等外部平台
- Dashboard 要有多个页面：审查结果界面(展示每份报告对应的 20 个审查要点结果，每个审查要点要求展示审查结果判别说明以及判断依据，并可跳转到对应的页面使得用户可以确认)，系统总览、数据浏览、Ingestion 管理、追踪查看、评估面板等

5. RAG 系统评估体系：可插拔评估框架，支持 Ragas 和自定义指标(hit_rate、MRR 等)

6. MCP 集成：用 Python 官方 MCP SDK， 暴露 tools (query_knowledge_hub、list_collections、get_document_summary 等)

7. 数据摄取：PDF → Markdown (用 MarkItDown 以及 MinerU) → 分块 → LLM 增强(重写、元数据注入、图片描述) → 双路 Embedding → Pg Vector Upsert，支持 SHA256 增量跳过
